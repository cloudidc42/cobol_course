## ขั้นตอนที่ 12: ติดตั้ง GnuCOBOL บน Windows

### วิธีที่ 1: ใช้ MSYS2 (แนะนำที่สุด)

1. ดาวน์โหลดและติดตั้ง [MSYS2](https://www.msys2.org/) จากเว็บไซต์ทางการ
2. เปิดโปรแกรม **MSYS2 MSYS** แล้วอัปเดตแพ็กเกจก่อน:

```bash
pacman -Syu
```

3. หลังจากอัปเดตเสร็จ (อาจต้องปิดแล้วเปิดใหม่ 1 ครั้ง) ให้ติดตั้ง GnuCOBOL:

```bash
pacman -S mingw-w64-x86_64-gnucobol3
```

4. เพิ่ม path `C:\msys64\mingw64\bin` เข้าไปใน **Environment Variables > Path** ของ Windows
   เพื่อให้เรียกคำสั่ง `cobc` ได้จาก Command Prompt หรือ PowerShell ทั่วไป

5. เปิด Command Prompt ใหม่ แล้วทดสอบด้วยคำสั่ง:

```bash
cobc --version
```

หากติดตั้งสำเร็จ จะเห็นข้อความคล้ายกับ:

```
cobc (GnuCOBOL) 3.2.0
Copyright (C) 2020 Free Software Foundation, Inc.
```

### วิธีที่ 2: ใช้ WSL (Windows Subsystem for Linux)

หากคุณคุ้นเคยกับ Linux อยู่แล้ว แนะนำให้ติดตั้ง WSL2 แล้วทำตามคำแนะนำสำหรับ **Linux (Ubuntu)** ในขั้นตอนที่ 14
วิธีนี้ให้ประสบการณ์ที่เสถียรและใกล้เคียงกับ Production Server มากที่สุด

```powershell
wsl --install -d Ubuntu
```

จากนั้นเปิด Ubuntu Terminal และทำตามขั้นตอนที่ 14

### แบบฝึกหัดที่ 12.1

**โจทย์**: หลังติดตั้งเสร็จ รันคำสั่ง `cobc --version` แล้วบันทึกเวอร์ชันที่ได้ (ควรเป็น 3.x ขึ้นไป)

## ขั้นตอนที่ 13: ติดตั้ง GnuCOBOL บน macOS

### ใช้ Homebrew (แนะนำ)

1. หากยังไม่มี Homebrew ให้ติดตั้งก่อนด้วยคำสั่งนี้ใน Terminal:

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

2. ติดตั้ง GnuCOBOL:

```bash
brew install gnu-cobol
```

> **หมายเหตุ**: ชื่อแพ็กเกจใน Homebrew อาจเปลี่ยนแปลงได้ตามเวลา หากคำสั่งข้างต้นไม่พบแพ็กเกจ
> ให้ลองค้นหาด้วย `brew search cobol` เพื่อดูชื่อแพ็กเกจล่าสุด

3. ตรวจสอบการติดตั้ง:

```bash
cobc --version
```

### แบบฝึกหัดที่ 13.1

**โจทย์**: หากพบข้อความ `command not found: cobc` หลังติดตั้ง ให้ลองรันคำสั่ง `brew link gnu-cobol`
แล้วเปิด Terminal ใหม่อีกครั้ง จากนั้นทดสอบใหม่

## ขั้นตอนที่ 14: ติดตั้ง GnuCOBOL บน Linux

### Ubuntu / Debian

```bash
sudo apt update
sudo apt install gnucobol4
```

> หากระบบของคุณไม่พบแพ็กเกจ `gnucobol4` ให้ลองใช้ `gnucobol3` หรือ `open-cobol` ตามเวอร์ชันที่ distro รองรับ:

```bash
sudo apt install gnucobol3
```

### Fedora / RHEL / CentOS

### Arch Linux

## ขั้นตอนที่ 15: ตรวจสอบการติดตั้งอย่างละเอียดและทำความเข้าใจ cobc

`cobc` คือชื่อคำสั่งของคอมไพเลอร์ GnuCOBOL (ย่อมาจาก **CO**BOL **C**ompiler) ลองรันคำสั่งต่อไปนี้เพื่อดูข้อมูลเพิ่มเติม:

```bash
cobc --info
```

คำสั่งนี้จะแสดงข้อมูลสภาพแวดล้อมโดยละเอียด เช่น เวอร์ชัน, C Compiler ที่ใช้เบื้องหลัง (GnuCOBOL แปลง COBOL
เป็นภาษา C ก่อนคอมไพล์เป็นไฟล์ execution จริง), และ path ต่าง ๆ ที่เกี่ยวข้อง

### ทำไม GnuCOBOL ถึงต้องใช้ C Compiler ด้วย

สิ่งสำคัญที่ควรรู้คือ GnuCOBOL ทำงานโดย **แปลงโค้ด COBOL เป็นโค้ดภาษา C ก่อน** แล้วจึงใช้ C Compiler
(เช่น GCC) แปลงเป็นไฟล์ execute ที่เครื่องรันได้จริงอีกที ดังนั้นระบบของคุณจำเป็นต้องมี GCC หรือ
C Compiler ติดตั้งอยู่ด้วย โดยทั่วไป:

- **Windows (MSYS2)**: ติดตั้งมาพร้อมกันแล้วเมื่อติดตั้ง `mingw-w64-x86_64-gnucobol3`
- **macOS**: ต้องมี Xcode Command Line Tools (`xcode-select --install`)
- **Linux**: ต้องมี `gcc` และ `build-essential` (Ubuntu: `sudo apt install build-essential`)

### แบบฝึกหัดที่ 15.1

**โจทย์**: รันคำสั่ง `gcc --version` บนเครื่องของคุณ หากไม่พบคำสั่งนี้ ให้ติดตั้งตามคำแนะนำข้างต้นของระบบปฏิบัติการคุณ
ก่อนไปขั้นตอนถัดไป

## ขั้นตอนที่ 16: ติดตั้งและตั้งค่า VS Code สำหรับเขียน COBOL

### ติดตั้ง VS Code

ดาวน์โหลดและติดตั้ง [Visual Studio Code](https://code.visualstudio.com/) ตามระบบปฏิบัติการของคุณ (ฟรี 100%)

### ติดตั้ง Extension สำหรับ COBOL

1. เปิด VS Code
2. ไปที่แถบ Extensions (ไอคอนสี่เหลี่ยมด้านซ้าย หรือกด `Ctrl+Shift+X` / `Cmd+Shift+X`)
3. ค้นหา **"COBOL"** แนะนำ Extension ยอดนิยม เช่น **"COBOL"** โดย Bitlang หรือ **"IBM Z Open Editor"**
   ซึ่งให้ Syntax Highlighting, Code Snippet และการตรวจสอบคอลัมน์ (Column Ruler) ที่สำคัญมากสำหรับ Fixed-Format
4. คลิก Install

### ตั้งค่า Column Ruler (สำคัญมากสำหรับ Fixed-Format COBOL)

เนื่องจากหลักสูตรนี้ใช้ Fixed-Format เป็นหลัก (คอลัมน์ 8–72) การเห็นเส้นแบ่งคอลัมน์ใน Editor จะช่วยได้มาก
เปิดไฟล์ `settings.json` ของ VS Code (`Ctrl+Shift+P` → พิมพ์ "Preferences: Open User Settings (JSON)")
แล้วเพิ่มบรรทัดนี้:

```json
{
  "editor.rulers": [7, 11, 72]
}
```

เส้นที่ตำแหน่ง 7 และ 11 จะช่วยแบ่งเขต Area A (คอลัมน์ 8-11) และ Area B (คอลัมน์ 12-72) ซึ่งเราจะอธิบาย
รายละเอียดกฎการเขียนคอลัมน์ใน **Part 003**

### แบบฝึกหัดที่ 16.1

**โจทย์**: เปิด VS Code และตรวจสอบว่า Extension COBOL ติดตั้งสำเร็จโดยดูที่แถบ Extensions ว่าสถานะเป็น "Installed"

## ขั้นตอนที่ 17: สร้างโครงสร้างไฟล์โปรเจกต์ที่แนะนำ

ก่อนเริ่มเขียนโค้ด เรามาสร้างโฟลเดอร์สำหรับเก็บงานทั้งหมดตลอดหลักสูตรกัน แนะนำโครงสร้างดังนี้:

```
cobol-learning/
├── part-001-hello-world/
│   └── hello.cob
├── part-002-.../
├── exercises/
└── projects/
```

สร้างโฟลเดอร์หลักด้วยคำสั่ง (Linux/macOS):

```bash
mkdir -p ~/cobol-learning/part-002-hello-world
cd ~/cobol-learning/part-002-hello-world
```

หรือบน Windows (Command Prompt):

```cmd
mkdir %USERPROFILE%\cobol-learning\part-002-hello-world
cd %USERPROFILE%\cobol-learning\part-002-hello-world
```

> **ข้อควรระวัง**: ชื่อไฟล์ COBOL แบบดั้งเดิมมักใช้นามสกุล `.cob` หรือ `.cbl` ทั้งสองแบบใช้ได้กับ GnuCOBOL
> หลักสูตรนี้จะใช้ `.cob` เป็นมาตรฐาน

### แบบฝึกหัดที่ 17.1

**โจทย์**: สร้างโฟลเดอร์ `cobol-learning` บนเครื่องของคุณ พร้อมโฟลเดอร์ย่อย `exercises` และ `projects`
ตามโครงสร้างข้างต้น

## ขั้นตอนที่ 18: เขียนโปรแกรม "Hello, World!" โปรแกรมแรกของคุณ

ถึงเวลาเขียนโค้ดจริงแล้ว! เปิด VS Code สร้างไฟล์ชื่อ `hello.cob` ในโฟลเดอร์ `part-002-hello-world`
แล้วพิมพ์โค้ดต่อไปนี้ **ด้วยตัวเอง** (อย่า copy-paste ตามที่แนะนำใน Part 001):

```cobol
      *> ===================================================
      *> Program : hello.cob
      *> Purpose : First COBOL program of the course
      *> ===================================================
       IDENTIFICATION DIVISION.
       PROGRAM-ID. HELLO-WORLD.
       AUTHOR. STUDENT-NAME.

       PROCEDURE DIVISION.
           DISPLAY "Hello, World! Welcome to COBOL.".
           DISPLAY "This is my first COBOL program.".
           STOP RUN.
```

> **ทำไมโค้ดตัวอย่างในหลักสูตรนี้ใช้ข้อความภาษาอังกฤษใน `DISPLAY` เสมอ**: นี่ไม่ใช่แค่ธรรมเนียมปฏิบัติ
> แต่เป็นข้อจำกัดทางเทคนิคที่สำคัญมาก — ดูรายละเอียดในหัวข้อ "ข้อควรระวัง" ท้ายขั้นตอนที่ 18 ด้านล่าง

### สิ่งสำคัญที่ต้องระวังเรื่องคอลัมน์ (Column Position)

โค้ด COBOL แบบ Fixed-Format มีกฎเรื่องตำแหน่งคอลัมน์ที่เคร่งครัดมาก (จะอธิบายละเอียดใน Part 003)
สิ่งที่ต้องจำไว้ก่อนตอนนี้คือ:

- **คอลัมน์ 1-6**: สงวนไว้สำหรับหมายเลขบรรทัด (Sequence Number) — ปกติเว้นว่างไว้
- **คอลัมน์ 7**: ใช้สำหรับเครื่องหมาย `*` (comment line) หรือ `-` (continuation)
- **คอลัมน์ 8-11 (Area A)**: ใช้เขียนชื่อ Division, Section, Paragraph, และ Level Number 01/77
- **คอลัมน์ 12-72 (Area B)**: ใช้เขียนคำสั่งทั่วไปและรายละเอียดต่าง ๆ
- **คอลัมน์ 73 เป็นต้นไป**: ถูกละเว้นโดยคอมไพเลอร์ (สืบทอดมาจากยุคบัตรเจาะรู)

ในตัวอย่างข้างต้น สังเกตว่า `IDENTIFICATION DIVISION.` เริ่มที่คอลัมน์ 8 (Area A)
ส่วน `DISPLAY "Hello, World!...".` เริ่มเยื้องเข้าไปที่ประมาณคอลัมน์ 12 (Area B)

> **เคล็ดลับ**: ถ้าคุณตั้งค่า Editor Rulers ตามขั้นตอนที่ 16 แล้ว จะเห็นเส้นแนวตั้งช่วยกะตำแหน่งคอลัมน์ได้ง่ายขึ้นมาก

### ⚠️ ข้อควรระวังสำคัญ: อย่าใส่ข้อความภาษาไทยในซอร์สโค้ด COBOL แบบ Fixed-Format

นี่คือกับดักทางเทคนิคที่ผู้เริ่มต้นมักเจอและงงว่าทำไม compile ไม่ผ่าน: **ตัวนับคอลัมน์ 72 ของ GnuCOBOL
นับเป็น "ไบต์" (byte) ไม่ใช่ "ตัวอักษร" (character)** ตัวอักษรภาษาไทยใน UTF-8 หนึ่งตัวใช้พื้นที่ 3 ไบต์
ในขณะที่ตัวอักษรภาษาอังกฤษใช้เพียง 1 ไบต์ ดังนั้นข้อความภาษาไทยที่ดูสั้นเมื่อนับเป็นตัวอักษร
อาจเกินขอบเขตคอลัมน์ 72 ไปมากเมื่อนับเป็นไบต์จริง ทำให้ compiler ตัดบรรทัดกลางคำสั่งและเกิด error เช่น
`continuation character expected` ทั้งที่โค้ดดูถูกต้องทุกประการเมื่อมองด้วยตา

**กฎของหลักสูตรนี้**: โค้ด COBOL ทุกตัวอย่างในหลักสูตร (comment, ชื่อตัวแปร, และข้อความใน `DISPLAY`)
จะเขียนเป็น**ภาษาอังกฤษเสมอ** ทั้งนี้ยังตรงกับธรรมเนียมปฏิบัติจริงในอุตสาหกรรม เพราะระบบ Mainframe จำนวนมาก
ใช้ Character Encoding แบบ EBCDIC ที่ไม่รองรับภาษาไทยโดยตรงอยู่แล้ว ส่วนคำอธิบายเป็นภาษาไทยทั้งหมด
จะอยู่ในเอกสาร Markdown นอกโค้ดแทน

### แบบฝึกหัดที่ 18.1

**โจทย์**: จงอธิบายว่าทำไมบรรทัดที่ขึ้นต้นด้วย `*>` ในตัวอย่างโค้ดข้างต้นจึงไม่ถูกคอมไพเลอร์นำไปประมวลผล

**เฉลย**: `*>` เป็นสัญลักษณ์ Comment แบบ Inline ของ GnuCOBOL (รองรับตั้งแต่ COBOL 2002) ที่สามารถวางไว้ตรงไหน
ของบรรทัดก็ได้ ทุกอย่างหลังเครื่องหมายนี้ในบรรทัดเดียวกันจะถูกคอมไพเลอร์มองข้ามไปทั้งหมด
ใช้สำหรับเขียนคำอธิบายโค้ดโดยไม่กระทบการทำงานของโปรแกรม

## ขั้นตอนที่ 19: คอมไพล์และรันโปรแกรมด้วยคำสั่ง cobc

### คอมไพล์โปรแกรม

เปิด Terminal (หรือ Command Prompt) ไปยังโฟลเดอร์ที่มีไฟล์ `hello.cob` แล้วรันคำสั่ง:

```bash
cobc -x -o hello hello.cob
```

อธิบาย flag แต่ละตัว:

| Flag | ความหมาย |
|---|---|
| `-x` | สร้างไฟล์ Executable ที่รันได้โดยตรง (ถ้าไม่ใส่ จะได้ Shared Module/Library แทน) |
| `-o hello` | กำหนดชื่อไฟล์ผลลัพธ์ (output) ว่า `hello` (บน Windows จะได้ `hello.exe` โดยอัตโนมัติ) |
| `hello.cob` | ไฟล์ต้นฉบับ (source file) ที่ต้องการคอมไพล์ |

หากไม่มี Error ใด ๆ คำสั่งนี้จะไม่แสดงข้อความอะไรเลย (Silent Success) และจะได้ไฟล์ `hello`
(หรือ `hello.exe` บน Windows) เกิดขึ้นในโฟลเดอร์เดียวกัน

### รันโปรแกรม

บน Linux/macOS:

```bash
./hello
```

บน Windows (Command Prompt):

```cmd
hello.exe
```

### ผลลัพธ์ที่คาดหวัง

```
Hello, World! Welcome to COBOL.
This is my first COBOL program.
```

**ยินดีด้วย! คุณเพิ่งรันโปรแกรม COBOL โปรแกรมแรกในชีวิตสำเร็จแล้ว** 🎉

### แบบฝึกหัดที่ 19.1

**โจทย์**: แก้ไขโปรแกรม `hello.cob` ให้แสดงชื่อของคุณเอง (เป็นภาษาอังกฤษ ตามเหตุผลเรื่อง Fixed-Format
ที่จะอธิบายในขั้นตอนที่ 18) เพิ่มอีกหนึ่งบรรทัด เช่น `DISPLAY "My name is Somchai.".`
แล้วคอมไพล์และรันใหม่อีกครั้ง

## ขั้นตอนที่ 20: ทำความเข้าใจ Free-Format และการแก้ปัญหา Compile Error เบื้องต้น

### Fixed-Format vs Free-Format

GnuCOBOL รองรับการเขียนโค้ดทั้งสองรูปแบบ:

- **Fixed-Format** (ค่าเริ่มต้น): ต้องเคร่งครัดเรื่องตำแหน่งคอลัมน์ตามที่อธิบายในขั้นตอนที่ 18
  เป็นรูปแบบดั้งเดิมที่ใช้บน Mainframe จริง — **หลักสูตรนี้ใช้รูปแบบนี้เป็นหลัก**
- **Free-Format**: ไม่ต้องสนใจตำแหน่งคอลัมน์ เขียนได้อิสระเหมือนภาษาโปรแกรมสมัยใหม่ทั่วไป
  เปิดใช้งานด้วย flag `-free` ตอนคอมไพล์ หรือใส่ directive `>>SOURCE FORMAT FREE` ที่ต้นไฟล์

ตัวอย่างเดียวกันในรูปแบบ Free-Format:

```cobol
>>SOURCE FORMAT FREE
IDENTIFICATION DIVISION.
PROGRAM-ID. HELLO-WORLD.
PROCEDURE DIVISION.
    DISPLAY "Hello, World! Welcome to COBOL.".
    STOP RUN.
```

คอมไพล์ด้วย:

```bash
cobc -x -free -o hello hello_free.cob
```

> **ทำไมหลักสูตรนี้ยังเน้น Fixed-Format**: แม้ Free-Format จะเขียนง่ายกว่า แต่ระบบ Legacy จริงในองค์กร
> (โดยเฉพาะบน Mainframe) เกือบทั้งหมดเขียนด้วย Fixed-Format การฝึกฝนด้วยรูปแบบนี้ตั้งแต่ต้น
> จะทำให้คุณอ่านและแก้ไขโค้ด Legacy จริงในที่ทำงานได้ทันทีโดยไม่ต้องปรับตัว

### Compile Error ที่พบบ่อยที่สุดสำหรับผู้เริ่มต้น

| ข้อความ Error | สาเหตุที่พบบ่อย | วิธีแก้ |
|---|---|---|
| `Error: PROCEDURE DIVISION header missing` | ลืมเขียน `PROCEDURE DIVISION.` หรือเขียนผิดตำแหน่งคอลัมน์ | ตรวจสอบว่าเขียนใน Area A (คอลัมน์ 8-11) |
| `Error: syntax error, unexpected ...` | ลืมใส่ period (`.`) ปิดท้ายประโยค | ตรวจสอบว่าทุกประโยคจบด้วย `.` |
| `cobc: command not found` | ยังไม่ได้ติดตั้ง GnuCOBOL หรือยังไม่ได้เพิ่ม PATH | กลับไปตรวจสอบขั้นตอนที่ 12-14 |
| โปรแกรมคอมไพล์ผ่านแต่รันแล้วไม่มีอะไรเกิดขึ้น | ลืม `STOP RUN.` หรือ error ใน logic | ตรวจสอบว่ามี `STOP RUN.` ปิดท้าย PROCEDURE DIVISION |
| ตัวอักษรภาษาไทยแสดงเป็นสัญลักษณ์แปลก ๆ | ปัญหา Character Encoding ของ Terminal | ตั้งค่า Terminal ให้ใช้ UTF-8 (เช่น `chcp 65001` บน Windows) |

### แบบฝึกหัดที่ 20.1 (แบบฝึกหัดสรุปท้าย Part)

**โจทย์**: จงตั้งใจทำให้เกิด Error โดยตั้งใจ 2 แบบ คือ (1) ลบ period ท้ายบรรทัด `DISPLAY` ออก
และ (2) ลบ `STOP RUN.` ออก แล้วลองคอมไพล์ดูว่า error message ที่ได้ตรงกับที่คาดไว้ในตารางหรือไม่
การฝึกทำ Error โดยตั้งใจแบบนี้จะช่วยให้คุณคุ้นเคยกับข้อความ Error และแก้ปัญหาได้เร็วขึ้นในอนาคต

## สรุปท้ายบท

ใน Part นี้ คุณได้:

- เข้าใจตัวเลือกสภาพแวดล้อมการพัฒนา COBOL และเหตุผลที่หลักสูตรนี้เลือก GnuCOBOL แบบติดตั้งเอง
- ติดตั้ง GnuCOBOL สำเร็จบนระบบปฏิบัติการของคุณ (Windows/macOS/Linux)
- เข้าใจว่า GnuCOBOL ทำงานร่วมกับ C Compiler เบื้องหลังอย่างไร
- ติดตั้งและตั้งค่า VS Code พร้อม Extension สำหรับ COBOL
- สร้างโครงสร้างโฟลเดอร์โปรเจกต์ที่จะใช้ตลอดหลักสูตร
- เขียน คอมไพล์ และรันโปรแกรม "Hello, World!" โปรแกรมแรกสำเร็จ
- เข้าใจความแตกต่างระหว่าง Fixed-Format และ Free-Format
- รู้จัก Compile Error พื้นฐานที่พบบ่อยและวิธีแก้ไข
